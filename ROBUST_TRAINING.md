# Training and comparing a robust candidate

This document describes protocol 1, whose confirmation results have already
been inspected. Rerunning it reproduces the previous study; it does not provide
another independent confirmation. Protocol 2 is described in
[EXPANDED_ROBUST_TRAINING.md](EXPANDED_ROBUST_TRAINING.md).

`train_robust.py` trains a separate checkpoint, compares both models on paired
populations, and can adopt the candidate only if every predefined criterion
is met. The active checkpoint is required for comparison; a CSV of previous
results is not a substitute.

From the project root, with the Python environment activated:

```powershell
python train_robust.py --seed 17029 --adopt-if-superior
```

The command uses the current `weights/classifier.pt` checkpoint to obtain the
simulation configuration and as the comparison reference. The candidate is
trained from scratch. The original SQLite database is unnecessary: new signals
are generated by the project's simulator with the same RS/CH/FS source
parameters. No biological data is used.

Each run gets a new directory under `artifacts/research/`. Original research
result files are not overwritten. CPU execution is supported; the RX 6600 is
not used by this training. `--threads 8` limits computation threads, while
`--epochs` and `--patience` control maximum duration.

## Fitting, selection, and calibration

With default settings, each split contains 25 configurations:

| Split | Neurons per class/configuration | Total | Purpose |
|---|---:|---:|---|
| `train` | 200 | 15,000 | Optimize weights |
| `selection` | 50 | 3,750 | Select the epoch and adjust the learning rate |
| `calibration` | 50 | 3,750 | Fit a confidence temperature |

Splits use distinct seeds and namespaces. Trace-identity checks prevent exact
overlap. Normalization uses training data only. Silent examples remain included
with their source parameter family; the program does not assume that the
family is observable in every signal.

Training includes:

- Constant currents with observation noise and parameter variation.
- Pulses with varied onsets and durations, including pulses ending at the
  window boundary and short late pulses.
- Ramps and sinusoids, including noisy versions.
- Networks with strengths 0.15, 0.4, and 0.8, and network/pulse and network/ramp
  combinations.

Exact configuration details, seeds, requested topology, and code hashes are
recorded in the checkpoint and `training.json`. The architecture remains
`NeuronClassifier1D`, with the same input interface as the application.
AdamW uses an initial learning rate of 0.001 and weight decay of 0.0001;
training uses label smoothing of 0.03. Selection uses NLL without smoothing.

The best epoch is selected by NLL on the `selection` split, with learning-rate
reduction and early stopping. The default maximum is 40 epochs with patience 8.
Only after selecting weights is a positive temperature fitted on the
`calibration` split using a fixed grid from 0.1 to 10, including 1. This fit
does not change the winning class: it changes probabilities.

The candidate's confidence threshold remains 0.70; it is not chosen on the
test set. Temperature, normalization, classes, and protocol accompany the
weights. Inference in the interface, worker, benchmark, and robustness study
applies this temperature; earlier checkpoints default to 1.

## Final comparison

Testing uses namespaces distinct from the three fitting splits and seeds
**6101, 6203, 6301, 6407, and 6503**, different from the previous diagnostic
study. There are 20 conditions with 100 neurons per class/seed by default:
**30,000 signals per model**, always using the same signals for both models.

| Group | Conditions |
|---|---|
| Reference | Independent neurons with the original settings |
| Noise | 2, 5, and 10 mV |
| Parameter variation | 0.06, 0.10, and 0.15 |
| Network | Strengths of 0.1, 0.5, and 1.0 |
| Pulse | Onsets at 10%, 30%, 50%; additional pulse starting at 55% with 35% duration |
| Families already used in training | Ramp and sinusoid with new populations |
| Families absent from fitting | Double pulse and triangular envelope |
| External constant amplitude | Below and above the recorded base range |

The double pulse has two active periods, at 10–30% and 60–80% of the window.
The triangular envelope rises from 0.25 to 1.75 times the amplitude and returns.
Neither enters training, selection, or calibration.

Ramps and sinusoids become part of candidate training. Their results with new
seeds test new populations, **not** generalization to wholly absent input
families. Gaussian variation likewise does not create rigorously disjoint
parameter ranges.

External constant ranges are approximately -7.5–5 and 30–42.5 under the default
protocol. Boundaries 5 and 30 are excluded using float32. This holdout concerns
the base amplitude of constant currents: instantaneous values above 30 can
occur in training ramps.

All neurons enter primary accuracy; silence is not removed. Confusion matrices,
macro F1, NLL, Brier, ECE, coverage, and accepted errors are computed separately.
Coverage uses the application's legacy counter (observed samples ≥29 mV) and
each checkpoint's threshold. It is not equivalent to physical-event counts or
the previous study's edge counter.

Prior current-range rejection is bypassed in this diagnostic analysis to
measure out-of-domain errors. The interface retains its operational domain
policy. Both models receive only signals; labels, parameters, and current
information do not enter the predictors.

## Adoption criteria

Criteria are defined before generating the final test:

| Criterion | Requirement |
|---|---|
| Mean accuracy across the 20 conditions | Gain of at least 2 percentage points |
| Mean pulse accuracy | Gain of at least 10 percentage points |
| Reference accuracy | At least 99%, with a maximum drop of 1 percentage point |
| Drop in any condition | At most 3 percentage points |
| Mean coverage | Maximum drop of 5 percentage points |
| Accepted errors per requested neuron | Mean reduction of at least 15% |
| Mean NLL | Lower than the reference |
| Mean Brier score | No worse than the reference |
| Per-seed gain | Positive mean gain for each of the five seeds |

These limits are an engineering policy, not a formal statistical significance
test. Connected neurons are correlated; the five seeds must not be interpreted
as thousands of independent networks. Each condition receives equal weight in
the average, and comparisons are paired.

If any criterion fails, the active checkpoint stays unchanged. Training is not
automatically retuned after observing the test. Another development round
requires confirmation tests with conditions and seeds not yet used for
development decisions.

## Using a trained candidate

An available trained candidate can be evaluated without retraining. Keep it
under a different name from the active checkpoint:

```powershell
python train_robust.py --candidate weights/classifier_robust_candidate.pt --adopt-if-superior
```

Without `--adopt-if-superior`, the program only compares. With this option and
all criteria met, it verifies the compared files' hashes, keeps an exact copy
of the previous checkpoint, and atomically replaces the active checkpoint.
The backup is named `classifier.original_<hash>.pt` in the same directory.
Paths and hashes are recorded in `adoption.json`.

Restart `python main_app.py` to load the adopted model. An older `.exe`
distribution contains its own files; after adopting and verifying a candidate,
rebuild it on Windows:

```powershell
.\build_windows.ps1 -SkipDependencyInstall
```

Do not copy the candidate directly over `weights/classifier.pt` before
comparison. To revert, close the application and restore the backup at the
path recorded in `adoption.json`.

## Evidence produced

- `training/candidate.pt`: trained weights, normalization, temperature, and
  provenance, including hashes of traces used in all three splits;
- `training/training.json`: protocol, seeds, versions, selected epoch, and
  calibration result;
- `training/training_history.csv`: training and selection curves;
- `comparison/comparison.json`: full results for both models per condition/seed,
  hashes, and each criterion's decision;
- `comparison/comparison.csv`: a table per condition/seed/model;
- `comparison/comparison.md`: a readable comparison and adoption criteria;
- `adoption.json`: the adoption record, when adoption occurs;
- `status.json`: execution status; incomplete results do not authorize adoption.

The command rejects nonempty output directories. A run without the reference
model can use `--train-only --context-study path/to/study.json` solely to build
a candidate from the recorded configuration. It ends as
`trained_awaiting_comparison`, without declaring superiority or adopting weights.
